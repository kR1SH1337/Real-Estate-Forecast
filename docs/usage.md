# Прогноз площади продаж за кеш и рассрочки в Москве

Основная модель: Хьюбер на всей доступной истории, в ценах января 2023 года. Фактор — средняя КС за три предыдущих месяца. Конечный результат — прогноз по годам в постоянных ценах и площади. Скользящее окно 24 месяца сохранено только как дополнительное сравнение.

## Структура проекта

| Путь | Назначение |
|---|---|
| `cash_model.py` | Код модели и точка запуска |
| `requirements.txt` | Зависимости Python |
| `data/` | Очищенный CSV продаж, Excel-файлы КС/индекса и явное допущение цен |
| `docs/` | Описание методологии и диагностики |
| `reference_results/` | Контрольный расчёт на исходных данных до сентября 2026 |
| `results/` | Результаты новых запусков; создаётся автоматически и не включается в Git |
| `archive/` | Исходный ZIP-пакет для истории; рабочие файлы находятся вне архива |

После обновления данных запускайте код заново. Новые результаты появляются в `results/`, а контрольный расчёт в `reference_results/` сохраняется для сравнения. Сохранение исходных файлов в GitHub выполняется отдельно от запуска модели.

## Запуск

Откройте терминал в корне репозитория `Real-Estate-Forecast`:

```bash
python -m pip install -r requirements.txt
python cash_model.py
```

В Windows при необходимости используйте `py` вместо `python`. Требуется Python 3.10+. В `data/` включены CSV очищенных продаж и исходные файлы КС и индекса цен. По умолчанию прогноз строится до декабря 2030 года, базовая цена января 2023 — **282 700 руб./м²**. Будущий прогноз цен не нужен.

Итоговый файл: `results/forecast_annual.csv`. Та же таблица печатается в терминале. Два главных столбца:

- `real_bln_rub` — млрд руб. в ценах января 2023;
- `area_mln_m2` — млн м² продаж за кеш/рассрочки.

Для текущего года таблица объединяет фактическую расчётную часть и прогноз оставшихся месяцев; это отмечено в `status`. Для будущих лет — полный прогноз. При неполном годе есть флаг `full_year=False`, при пропущенных фактических объёмах годовой итог не заполняется автоматически.

## Ожидаемый результат на данных до сентября 2026

| Год | Млрд руб. в ценах января 2023 | Млн м² |
|---|---:|---:|
| 2026, история + прогноз | 382,448 | 1,352839 |
| 2027 | 387,670 | 1,371313 |
| 2028 | 319,792 | 1,131208 |
| 2029 | 289,647 | 1,024573 |
| 2030 | 289,647 | 1,024573 |

Модель: `real = -4.1635169 + 2.8300753 * KS_avg3`. В 2029–2030 КС в исходном сценарии равна 10%, поэтому при фиксированных коэффициентах прогнозы одинаковы.

## Почему используем постоянные цены

Номинальная стоимость продаж содержит и изменение площади/структуры сделок, и изменение цен. Дефлирование общим индексом цен Москвы устраняет общий ценовой эффект:

`price_factor_t = price_index_t / price_index_Jan2023`

`real_t = nominal_t / price_factor_t`

Затем прогноз площади рассчитывается по базовой цене:

`area_m2 = real_bln_rub * 1_000_000_000 / base_price_rub_m2`

`area_mln_m2 = real_bln_rub * 1_000 / base_price_rub_m2`

При цене 282 700 руб./м² это эквивалентно `area_mln_m2 = real_bln_rub / 282.7`.

Это условный перевод, а не непосредственно наблюдаемая площадь: предполагаем, что цена метра сегмента кеша/рассрочек в январе 2023 равна средней рыночной цене Москвы, а последующая ценовая динамика сегмента совпадает с общим индексом. Изменение классов, районов, состава объектов и источников может нарушать это соответствие. Будущий индекс цен для перевода в площадь не требуется. Дефлирование само по себе не устраняет статистическую эндогенность КС или ошибки восстановленного ряда.

## Параметры запуска

```bash
python cash_model.py --end-year 2030 --base-price-rub-m2 282700 --output results
```

Цена задаётся **в рублях**, а не в тысячах рублей. Меняя её, согласуйте цену с январём 2023 — базой дефлирования. Цена меняет только площадь и масштаб её абсолютных ошибок; коэффициенты модели и реальные объёмы остаются прежними.

```bash
python cash_model.py --as-of 2025-04-01 --end-year 2030 --output results_2025_04
```

`--as-of` ограничивает обучающую историю. По умолчанию `--scope expanding` использует всю историю до этой даты. При обновлении добавляются новые месяцы, прежние остаются. В прогнозном горизонте коэффициенты фиксированы.

```bash
python cash_model.py --scope rolling --window 24 --output results_rolling
```

Rolling — дополнительная оценка, не основной выбор. `--window 24` также задаёт первую дату исторической проверки; основную расширяющуюся историю он не обрезает.

```bash
python cash_model.py --horizon 12 --bootstrap 0 --no-charts
```

`--horizon` задаёт число прогнозных месяцев и имеет приоритет над `--end-year`. Неполный последний год помечается. `--bootstrap 0 --no-charts` ускоряет запуск. По умолчанию 1000 повторов wild bootstrap с seed 20261009. Интервалы относятся к коэффициентам, не к годовой площади.

## Фактический индекс сентября

В `data/price_index.xlsx` включена неизменённая выгрузка ДОМ.РФ `analytics_2699287266.xlsx` по сентябрь 2026. Значение Москва / Общий / Все: **241,72054**; январь 2023: 140,23915. Предыдущая история индекса не пересмотрена. Расчёт проходит в строгом режиме: `python cash_model.py --no-price-assumptions`.

Историческое допущение в `data/price_assumptions.csv` сохранено только для воспроизведения предварительного расчёта с `archive/price_index_2026-08.xlsx`. Фактический индекс имеет приоритет. В текущем расчёте `price_index_assumed=False`, `provisional=False`, список применённых допущений пуст. Другие пропуски автоматически не заполняются.

Исходные продажи можно читать напрямую: `python cash_model.py --cash "Продажи и ипотека (1).xlsx" --prices "analytics_2699287266.xlsx"`. Код выбирает номинальную строку «Кеш/рассрочки» в группе «Продажи, млрд руб.». Старый двухстрочный Excel-формат поддерживается.

## Источники

- `data/cash_sales.csv`: колонки `date,nominal_bln_rub`; 45 месяцев, январь 2023 — сентябрь 2026. Неположительные остатки признаются пропусками; февраль 2023 исключён из обучения.
- `data/price_assumptions.csv`: дата допущения, дата исходного фактического индекса, метод `carry_forward`, причина. Историческое допущение сентября; с фактической выгрузкой не применяется.
- `data/provenance.json`: происхождение данных, исходный лист/строка, единицы и SHA-256 книги.
- `archive/cash_sales_2026-08.xlsx`: прежний ряд, сохранён для воспроизведения предыдущих расчётов.
- `data/macro_scenario.xlsx`: лист `Москва`, A — начало месяца, B — КС в процентах; история и будущий сценарий.
- `data/price_index.xlsx`: первый лист, строка `Город Москва / Общий / Все`; далее месяцы вида `Январь 2023` и индекс цен. База берётся по январю 2023, а не по среднему за год.

Стандартные пути к данным и папке `results/` отсчитываются от расположения `cash_model.py`, поэтому запуск возможен из любой рабочей папки. Явно переданные относительные пути отсчитываются от текущей папки терминала.

Пути можно менять через `--cash`, `--macro`, `--prices`. Если структура Excel-файлов изменится, адаптируйте `read_sources()`. Код не заполняет отсутствующие ставки. Для цен допустимы только месяцы, явно перечисленные в файле допущений; фактические значения всегда приоритетны. Иные пропуски вызывают ошибку. Код и не меняет исходные Excel-файлы.

## Проверка и ограничения

Основной исторический тест в площади: RMSE около **0,265 млн м²**, MAPE **13,22%**, WAPE **13,01%**, смещение **+13,01%**. При делении реальных объёмов на постоянную базовую цену относительные ошибки не меняются. Это оценка относительно восстановленной площади, а не отдельной статистики зарегистрированных метров.

Десять 12-месячных горизонтов перекрываются; будущая КС известна. Фактический индекс цен нужен для формирования проверочного реального ряда, но будущий индекс не входит в прогноз площади. Номинальные метрики в JSON оставлены только как дополнительная проверка с фактическими будущими ценами.

44 пригодных наблюдения, неодинаковый разброс ошибок и структурные изменения ограничивают надёжность. Прогноз до 2030 — условный на сценарий КС и сохранение оценённой связи. Код не моделирует самостоятельный долгосрочный рост рынка. Отрицательные значения не обрезаются автоматически; они помечаются и требуют пересмотра спецификации.
